# နန်းရိပ် အသုံးပြုနည်း

Group တွင် `/nanyate` သို့မဟုတ် `/နန်းရိပ်` ပို့ပါ။ Private ဂိမ်းခန်းခလုတ်ကိုဖွင့်ပြီး ပါဝင်မှုအတည်ပြုပါ။ အနည်းဆုံး ၈ ယောက်၊ အများဆုံး ၄၀ ယောက်ဖြစ်သည်။ အချိန်ပြည့်လျှင် အလိုအလျောက်စမည်။ လူပြည့်ပြီးလျှင် Admin က စောစောစနိုင်သည်။

- `/nanyate anonymous` — နာမည်ဝှက်ဆွေးနွေးမှု။ Private တွင် `/nychat <ပွဲ ID> <စာသား>`။ တစ်ဦးတစ်နေ့ စာနှစ်စောင်၊ တစ်စောင် ၃၅၀ စာလုံး။ လူများလျှင် ဆွေးနွေးချိန်တိုးသည်။
- `/nanyate advanced` — ဒုတိယည မှူးမတ်တစ်ဦးအား သစ္စာဖောက်ကမ်းလှမ်းမှု။
- `/nanyate anonymous advanced` — mode နှစ်မျိုးလုံး။
- `/nanyaterules` — စည်းမျဉ်း။
- `/nanyatestop` — Admin/Owner အတည်ပြုပြီး ပွဲဖျက်သိမ်း။

ညတွင် နေရာရွေး သို့မဟုတ် Role အစွမ်းသုံးပါ။ အစွမ်းသုံးလျှင် နေရာကို bot က သတ်မှတ်ပေးသည်။ လုပ်ကြံဘက်က အဖွဲ့တိုက်ခိုက်ပစ်မှတ်ကို ထပ်ရွေးနိုင်သည်။ အချိန်မကုန်မီ နောက်ဆုံးရွေးချယ်မှုကိုယူသည်။ တစ်ညလျှင် အဖွဲ့တိုက်ခိုက်မှုတစ်ကြိမ်သာဖြစ်သည်။

နေ့တွင် သက်သေဖော်၊ ဆွေးနွေး၊ ဆိုင်အသုံးပြုနိုင်သည်။ သက်သေစာရင်းကို public bulletin နှင့် private ဂိမ်းခန်းတွင် ကြည့်နိုင်သည်။ သက်သေက Role အတည်ပြုချက်မဟုတ်ပါ။ မဲချိန်မှ မဲပေးနိုင်သည်။

သံတမန်ဆက်သွယ်ခွင့်ရှိသူများသည် နေ့ဆွေးနွေးချိန်တွင် `/nywhisper <ပွဲ ID> <ပစ်မှတ်မျက်နှာဖုံးနံပါတ်> <စာသား>` သုံးနိုင်သည်။ ညသစ်စလျှင် ခွင့်ကုန်သည်။

Owner editor တွင် **နန်းရိပ်** ကိုရှာ၍ စာသား၊ Role အမည်/ရှင်းလင်းချက်၊ အချိန်၊ reward၊ Quest၊ ဆိုင်စျေး၊ optional Role ဖွင့်ပိတ်၊ အသုံးအကြိမ်၊ mode defaults ပြင်နိုင်သည်။ အခြေခံ Role ခြောက်မျိုးကို ပိတ်မရ။ အဆိပ်/ကျိန်စာကုသူပိတ်လျှင် သက်ဆိုင်ရာရန်ဘက်အစွမ်းကို role ခွဲရာတွင် မထည့်ပါ။ Settings သည် နောက်ပွဲမှသက်ရောက်သည်။

Owner Tools → Test Group → နန်းရိပ် သည် ဂိမ်းသစ်စာရင်းအပေါ်ဆုံးတွင်ရှိသည်။ ပုံမှန် deployment သည် group အားလုံးတွင် command ဖြင့်စနိုင်သည်။ Test mode ရွေးလျှင် ရွေးထားသော group များတွင်သာ ပွဲအသစ်စနိုင်သည်။

## စစ်ဆေးမှုနှင့် ကန့်သတ်ချက်

Pure engine tests သည် Role ၃၂ မျိုး၊ လူ ၈–၄၀ အတွက် role အစု ၁,၉၈၀၊ ပွဲတု ၃,၀၀၀၊ AFK၊ မဲတူ၊ အဆိပ်/ကာကွယ်/ပိတ်ဆို့၊ ကျိန်စာ၊ အစွမ်းကူး၊ သစ္စာဖောက်၊ serialization ကိုစစ်သည်။ Telegram handler tests သည် stale ခလုတ်၊ private recipient၊ outsider၊ deadline၊ quest duplicate၊ stop confirmation ကိုစစ်သည်။ DB reward marker နှင့် points သည် transaction တစ်ခုတည်းဖြစ်သည်။

Automated random players သည် လူအစစ်၏ လှည့်စားမှုနှင့် ဆွေးနွေးမှုကို မတုပနိုင်၍ human balance ကို အာမခံမရ။ ပွဲအတွင်းစာသားကို Telegram သို့ပို့ပြီးနောက် DB acknowledgement မအောင်မြင်လျှင် စာတစ်စောင်ထပ်ပေါ်နိုင်သော်လည်း game action/reward ကို ထပ်မတွက်ပါ။ Group နှင့် private cards များကို ပြင်သုံးပြီး အများသိသက်သေကို စုပြထားသည်။ Bot worker သည် group စာပို့မှုကို pace လုပ်သည်။
